# UEBA_proj
This project is about UEBA approach. Ml model, detecting anomalies in net traffic etc.

UEBA-VAE: обнаружение аномальной активности на Windows

Программный прототип для выявления необычного локального и сетевого поведения персонального компьютера методами машинного обучения. Проект реализует базовый подход UEBA (User and Entity Behavior Analytics): сбор телеметрии, построение профиля нормальной работы, вычисление оценки аномальности и формирование отчёта.

1. Назначение проекта

Программа собирает обезличенные агрегированные показатели работы Windows-компьютера и анализирует их с помощью вариационного автоэнкодера (VAE). Модель обучается преимущественно на нормальной активности. Если новое окно наблюдений восстанавливается моделью значительно хуже обычного, оно помечается как аномальное.

Прототип предназначен для учебного исследования и не является готовой промышленной системой защиты информации.

2. Основные возможности

работа на Windows;

сбор системной и сетевой телеметрии через psutil;

отсутствие сохранения имён пользователей, процессов, командных строк, путей, IP-адресов, номеров портов и содержимого пакетов;

агрегация измерений по временным окнам;

обучение VAE на нормальном поведении;

сохранение весов модели, параметров масштабирования и порога;

детерминированный инференс через среднее латентного распределения mu;

вывод результатов в pandas.DataFrame и возможность сохранения в CSV.

4. Собираемые показатели

Коллектор формирует одну строку на временное окно.

Системные показатели

средняя и максимальная загрузка CPU;

средняя и максимальная загрузка RAM;

использование swap;

среднее количество процессов;

количество новых процессов;

объём операций чтения и записи диска;

количество дисковых операций чтения и записи.

Сетевые показатели

отправленные и полученные байты;

отправленные и полученные пакеты;

среднее количество TCP-соединений и UDP-конечных точек;

количество соединений в состояниях ESTABLISHED, LISTEN и TIME_WAIT;

количество новых и закрытых соединений;

количество уникальных удалённых узлов и портов;

количество новых удалённых узлов;

среднее число соединений с глобальными и неглобальными IP-адресами;

отношение исходящего трафика к входящему.

IP-адреса и порты используются только в оперативной памяти для расчёта агрегатов и не записываются в CSV.

7. Сбор обучающей выборки

Терминал или PyCharm следует запустить от имени администратора.

Для финального 24-часового сбора с окном 15 секунд и измерением каждые 5 секунд:

python src\collector.py `
  --output data\raw\metrics_30s.csv `
  --sample-interval 5 `
  --window-seconds 15 `
  --duration-hours 24

Для короткой проверки работы коллектора:

python src\collector.py `
  --output data\test\new_metrics.csv `
  --sample-interval 5 `
  --window-seconds 15 `
  --max-windows 10

Для работы до ручной остановки:

python src\collector.py --continuous --window-seconds 15

Остановка выполняется сочетанием Ctrl+C. Коллектор завершает текущее действие и корректно закрывает CSV.

Важное условие воспроизводимости

Для обучения и последующего нормального тестирования следует использовать одинаковые:

версию collector.py;

длительность окна;

частоту измерений;

обычное состояние среды компьютера.

VPN заметно меняет число приватных соединений, удалённых портов, использование памяти и другие показатели. Если модель обучалась без VPN, запуск с VPN может корректно восприниматься как смена поведения и давать высокий anomaly score. Для проверки обычной работы состояние VPN должно совпадать с состоянием во время сбора обучающей выборки. Отдельное включение VPN можно использовать как контролируемый пример аномалии.
8. Подготовка данных

Данные сортируются по timestamp и разделяются без перемешивания:

70% — обучение;

15% — валидация;

15% — тест.

Такое разделение сохраняет временной порядок и предотвращает попадание будущих наблюдений в обучающую часть.

Из финального варианта модели исключены признаки:

weekday_sin
weekday_cos
hour_sin
hour_cos

В модель поступает 28 признаков.

Для счётчиков и показателей с тяжёлым правым хвостом применяется:

x = np.log1p(x)

После этого StandardScaler обучается только на обучающей части. Валидационная, тестовая и новая выборки преобразуются теми же параметрами mean_ и scale_.

Критически важно сохранять один и тот же набор и порядок признаков при обучении и инференсе. Для этого в scaler_params_B.npz сохраняются:

mean
scale
feature_names

9. Модель

Используется вариационный автоэнкодер со следующей конфигурацией:

Вход:                 28 признаков
Encoder:              28 → 56 → 28 → 14 MLP
Латентное пространство: 6 
Decoder:               6 → 56 → 56 → 28
Активации:             ReLU
Выходной слой:         Linear
Оптимизатор:           Adam
Learning rate:         0.001
Batch size:            64
Количество эпох:       150
β для KL-составляющей: 0.006

Функция потерь:

ELBO loss = MSE reconstruction loss + β × KL divergence

Линейный выход декодера используется потому, что после StandardScaler признаки могут иметь как положительные, так и отрицательные значения.

11. Интерпретация результата

anomaly_score <= threshold — окно соответствует известному модели нормальному поведению;

anomaly_score > threshold — окно заметно отличается от нормального профиля.

Высокий score не означает автоматически наличие вредоносной программы. Причиной могут быть:

включение VPN;

резкое увеличение числа соединений;

массовые операции чтения и записи диска;

необычный сетевой обмен;

реальная вредоносная или несанкционированная активность итд.

Для объяснения аномалии можно вычислить ошибку реконструкции отдельно по каждому признаку:

feature_errors = (x_tensor - reconstruction) ** 2

Признаки с максимальными значениями являются основными факторами срабатывания. Это не полноценная классификация угроз, но даёт первичное объяснение результата с точки зрения поведения системы.

13. Ограничения

модель знает только режимы, представленные в обучающей выборке;

изменение конфигурации ПК или сетевой среды может восприниматься как аномалия;

статистический порог не является гарантией обнаружения всех угроз;

модель не определяет точный тип атаки;

текущий inference.py обрабатывает последовательные строки из CSV-пакета; для строго непрерывного анализа его необходимо запускать циклически для новых окон либо объединить с коллектором в единый процесс;

результаты нельзя использовать как единственное основание для принятия решений по информационной безопасности.

# Итог

Разработанный прототип реализует базовый UEBA-конвейер для Windows: сбор обезличенной телеметрии, построение профиля нормального поведения с помощью VAE, загрузку сохранённой модели, расчёт оценки аномальности и формирование отчёта. Решение подходит для демонстрации полного ML-процесса и может быть расширено потоковым анализом, автоматическим объяснением аномалий и дополнительными источниками событий безопасности.
